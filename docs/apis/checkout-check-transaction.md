# Check transaction

Call this from your server after creating a payment (and when your callback URL is hit) to
confirm whether the payment succeeded before you fulfil the order. Used by
[Online checkout](../services/accept-payments/online-checkout.md) and
[Dynamic QR](../services/accept-payments/dynamic-qr.md).
Only transactions created within 7 days can be checked; for older ones the portal points to
[Get a transaction details](https://developer.payway.com.kh/get-a-transaction-details-14530824e0).

## Endpoint

| | Sandbox | Production |
|---|---|---|
| Method | `POST` | `POST` |
| URL | `https://checkout-sandbox.payway.com.kh/api/payment-gateway/v1/payments/check-transaction-2` | `https://checkout.payway.com.kh/api/payment-gateway/v1/payments/check-transaction-2` |
| Content-Type | `application/json` | |

Production base URL is from the portal's [API Endpoints](https://developer.payway.com.kh/api-endpoints-984508m0) page.
Rate limit: 600 requests/second.

## Authentication & hash

Fields concatenated **in this exact order**, then signed with
[`paywayHash`](../examples/node/payway-hash.md) using your API key:

1. `req_time`
2. `merchant_id`
3. `tran_id`

The field description on the portal mentions only `merchant_id` and `tran_id`; the portal's PHP
sample (`$req_time . $merchant_id . $tran_id`) includes `req_time`. This page follows the sample.

## Request fields

| Name | Type | Required | Rules / Description |
|---|---|---|---|
| `req_time` | string | Yes | Request date and time in UTC, `YYYYMMDDHHmmss`. |
| `merchant_id` | string | Yes | Merchant key provided by ABA Bank. |
| `tran_id` | string | Yes | Your purchase transaction ID. |
| `hash` | string | Yes | Base64 HMAC-SHA512, see above. |

## Response

```json
{
  "data": {
    "payment_status_code": 0,
    "total_amount": 0.1,
    "original_amount": 0.1,
    "refund_amount": 0,
    "discount_amount": 0,
    "payment_amount": 0.1,
    "payment_currency": "USD",
    "apv": "753786",
    "payment_status": "APPROVED",
    "transaction_date": "2025-02-13 13:55:25"
  },
  "status": {
    "code": "00",
    "message": "Success!",
    "tran_id": "17394277693"
  }
}
```

| Name | Type | Description |
|---|---|---|
| `data.payment_status_code` | integer | `0` APPROVED / PRE-AUTH, `2` PENDING, `3` DECLINED, `4` REFUNDED, `7` CANCELLED. |
| `data.total_amount` | number | Amount the customer is supposed to pay after discount. |
| `data.original_amount` | number | Original purchase amount. |
| `data.refund_amount` | number | Total of all refunded amounts. |
| `data.discount_amount` | number | Discount, in the original transaction currency. |
| `data.payment_amount` | number | Amount the customer paid. |
| `data.payment_currency` | string | Currency the customer paid in. |
| `data.apv` | string | Approval code. |
| `data.payment_status` | string | `APPROVED`, `PRE-AUTH`, `REFUNDED`, `PENDING`, `DECLINED`, `CANCELLED`. |
| `data.transaction_date` | string | Date and time the transaction was created in the gateway. |
| `status.code` | string | See Errors. |
| `status.message` | string | Message for `code`. |
| `status.tran_id` | string | Request ID generated by the gateway. |

## Errors

| Code | Meaning | What to do |
|---|---|---|
| `00` | Success! | Read `data.payment_status`. |
| `5` | Invalid hash | Check field order and API key. |
| `6` | Transaction not found | Check `tran_id`; only the last 7 days are searchable. |
| `8` | Invalid merchant profile | Check `merchant_id` / environment. |
| `11` | Internal server error | Retry later. |
| `429` | Reach request limit | Back off; limit is 600 requests/second. |

Exception example from the portal: `{"status": {"code": 6, "message": "Transaction not found", "tran_id": "1729573626"}}`.

## Pitfalls

- The path really ends in `check-transaction-2`.
- The portal schema nests `status` inside `data`, but its examples put `status` at the top level. Handle both until confirmed.
- `status.code` is a string (`"00"`) in the success example but a number (`6`) in the exception example — compare loosely.
- `status.code` `00` only means the lookup worked; the payment succeeded only when `data.payment_status` is `APPROVED`. Also compare the amount and currency with your stored order.
- Stop polling once a result is returned.
