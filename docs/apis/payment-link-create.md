# Create payment link

Call this from your server to create a payment link with an exact amount, then send the returned
`data.payment_link` URL to the customer (chat, SMS, email). When the customer pays, PayWay posts to
your `return_url`; then get the payment details with [Check transaction](checkout-check-transaction.md).

## Endpoint

| | Sandbox | Production |
|---|---|---|
| Method | `POST` | `POST` |
| URL | `https://checkout-sandbox.payway.com.kh/api/merchant-portal/merchant-access/payment-link/create` | `https://checkout.payway.com.kh/api/merchant-portal/merchant-access/payment-link/create` |
| Content-Type | `multipart/form-data` | |

Production base URL is from the portal's [API Endpoints](https://developer.payway.com.kh/api-endpoints-984508m0) page.

## Authentication & hash

Fields concatenated **in this exact order**, then signed with
[`paywayHash`](../examples/node/payway-hash.md) using your API key:

1. `request_time`
2. `merchant_id`
3. `merchant_auth`

`merchant_auth` is hashed in its final encrypted, Base64 form.

**`merchant_auth` encryption.** JSON-encode the object below, split the JSON into chunks of
117 bytes, encrypt each chunk with the **RSA public key provided by PayWay** (PHP
`openssl_public_encrypt`, default padding), concatenate the encrypted chunks and Base64-encode the result.

> The RSA padding mode is not named on the portal; PHP's `openssl_public_encrypt` default is PKCS#1 v1.5. Not documented on the portal — confirm with PayWay team.

## Request fields

| Name | Type | Required | Rules / Description |
|---|---|---|---|
| `request_time` | string | Yes | Request date and time in UTC, `YYYYMMDDHHmmss`. |
| `merchant_id` | string | Yes | Merchant key provided by ABA Bank. |
| `merchant_auth` | string | Yes | RSA-encrypted, Base64 JSON object (fields below). |
| `image` | binary | No | Image for the payment link. Max 3 MB; JPG, JPEG, PNG. |
| `hash` | string | Yes | Base64 HMAC-SHA512, see above. |

Fields inside `merchant_auth`:

| Name | Type | Required | Rules / Description |
|---|---|---|---|
| `mc_id` | string | Yes | Same value as `merchant_id`. |
| `title` | string(250) | Yes | Title of the payment link. |
| `amount` | string | Yes | At least 100 KHR or 0.01 USD. Cannot be null or zero. |
| `currency` | string | Yes | `KHR` or `USD`. |
| `description` | string(250) | No | Description of the payment link. |
| `payment_limit` | string | No | Maximum number of transactions for this link. Blank = no limit. |
| `expired_date` | string | Yes | When the link expires. Must be in the future; no maximum. `null` = no expiry. The portal's PHP sample uses a Unix timestamp (`time()`). |
| `return_url` | string | Yes | Base64-encoded URL that receives payment details. |
| `merchant_ref_no` | string(50) | No | Your payment link ID; included in the callback. PayWay does not check duplicates. |
| `payout` | string | No | Payout instructions, e.g. `[{"acc":"122092016015926","amt":0.01}]`. Total must equal the link amount. |

Callback to `return_url` (POST, `application/json`), from the
[Payment Link](https://developer.payway.com.kh/payment-link-3158157f0) guide:

```json
{ "tran_id": "123456789", "status": "00", "merchant_ref_no": "ref0001" }
```

## Errors

| Code | Meaning | What to do |
|---|---|---|
| `PTL02` | Wrong Hash | Check field order; hash the encrypted `merchant_auth` exactly as sent. |
| `PTL05` | Parameter Invalid Format | Check field formats inside `merchant_auth`. |
| `PTL99` | Merchant invalid currency. | Use a currency enabled on your profile. |
| `PTL132` | Invalid payment link. | Check the request data. |

Exception example: `{"status": {"code": "PTL02", "message": "Wrong Hash"}, "tran_id": 1681357410}`.

## Pitfalls

- This endpoint uses `request_time`, not `req_time` as the checkout APIs do.
- `merchant_auth` needs the separate **RSA public key** from PayWay, not your API key.
- Encrypt in 117-byte chunks of the UTF-8 JSON (bytes, not characters).
- `amount` is documented as a string inside `merchant_auth`, but the portal's PHP sample sends a number (`0.03`).
  > Not documented on the portal which form is required — confirm with PayWay team.
- The callback contains only `tran_id`, `status` and `merchant_ref_no`; use [Check transaction](checkout-check-transaction.md) with that `tran_id` for amount and status. Check transaction does not return the link `id` or `merchant_ref_no`, so also confirm the order's own link is `PAID` with [Get payment link details](payment-link-get-details.md), and accept each `tran_id` only once.
- Compute the amount on your server. See [Never trust client amounts](../best-practices/never-trust-client-amounts.md).
