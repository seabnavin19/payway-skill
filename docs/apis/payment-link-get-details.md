# Get payment link details

Call this from your server to look up a payment link created with
[Create payment link](payment-link-create.md), for example to see whether it is still `OPEN`
and how many payments it has received.

## Endpoint

| | Sandbox | Production |
|---|---|---|
| Method | `POST` | `POST` |
| URL | `https://checkout-sandbox.payway.com.kh/api/merchant-portal/merchant-access/payment-link/detail` | `https://checkout.payway.com.kh/api/merchant-portal/merchant-access/payment-link/detail` |
| Content-Type | `application/json` | |

Production base URL is from the portal's [API Endpoints](https://developer.payway.com.kh/api-endpoints-984508m0) page.

## Authentication & hash

Fields concatenated **in this exact order**, then signed with
[`paywayHash`](../examples/node/payway-hash.md) using your API key:

1. `request_time`
2. `merchant_id`
3. `merchant_auth`

`merchant_auth` is the JSON `{"mc_id": <merchant_id>, "id": <payment link id>}`, encrypted with the
RSA public key provided by PayWay in 117-byte chunks and Base64-encoded — the same method as
[Create payment link](payment-link-create.md).

## Request fields

| Name | Type | Required | Rules / Description |
|---|---|---|---|
| `request_time` | string | Yes | Request date and time in UTC, `YYYYMMDDHHmmss`. |
| `merchant_id` | string | Yes | Merchant key provided by ABA Bank. |
| `merchant_auth` | string | Yes | RSA-encrypted, Base64 JSON with `mc_id` and `id` (the payment link `data.id`). |
| `hash` | string | Yes | Base64 HMAC-SHA512, see above. |

## Response

> The portal gives no response example for this endpoint, only a schema. Not documented on the portal — confirm with PayWay team.

Top-level fields: `data` (object), `status` (object), `tran_id` (string).

| Name | Type | Description |
|---|---|---|
| `data.id` | string | Payment link ID generated by the gateway. |
| `data.title` | string | Title of the link. |
| `data.image` | object | `image` (full URL), `filename`, `size` (KB). |
| `data.amount` | number | Payment link amount. |
| `data.currency` | string | `KHR` or `USD`. |
| `data.status` | string | `OPEN` while `payment_limit` > `total_trxn`; `PAID` once they are equal (no more payments accepted). |
| `data.description` | string | Description of the link. |
| `data.payment_limit` | number | Maximum number of transactions. |
| `data.total_amount_org` | string | Total payment amount before refund. |
| `data.total_refund` | string | Total refunded amount of all related transactions. |
| `data.total_amount` | number | Total amount after refund. |
| `data.total_trxn` | number | Number of completed payments. |
| `data.created_at` / `data.updated_at` | string | Created / last updated date and time. |
| `data.expired_date` | number | Expiry timestamp. |
| `data.pushback_url` | string | URL PayWay calls with payment status. |
| `data.payment_link` | string | Payment link URL. |
| `status.code` | string | See Errors. |
| `status.message` | string | Message for `code`. |
| `tran_id` | string | Log ID generated by the gateway. |

## Errors

| Code | Meaning | What to do |
|---|---|---|
| `PTL02` | Wrong hash | Check field order; hash the encrypted `merchant_auth` exactly as sent. |
| `PTL132` | Invalid payment link | Check the payment link `id`. |

> The success code is not listed on this page (Create payment link returns `00`). Not documented on the portal — confirm with PayWay team.

## Pitfalls

- Content-Type is `application/json` here but `multipart/form-data` for Create payment link.
- The response calls the callback URL `pushback_url`; Create payment link calls it `return_url`.
- `id` is the payment link `data.id` from Create payment link (e.g. `UD/8Hl***Ht1xQdhlw==`), not the URL or `merchant_ref_no`.
